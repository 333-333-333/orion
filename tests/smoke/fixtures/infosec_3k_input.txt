# ORION Test Text: Information Security

Information security is a discipline focused on protecting information assets against internal and external threats. An information asset is any resource that has value for an organization and that stores, processes, transmits, or represents information. A confidential document is a type of information asset. A corporate database is a type of information asset. A customer record is a type of information asset. A source code repository is a type of information asset. A system configuration file is a type of information asset. A backup archive is a type of information asset. A business report is a type of information asset.

The purpose of information security is to preserve confidentiality, integrity, and availability. Confidentiality is a security property that ensures information is accessible only to authorized entities. Integrity is a security property that ensures information is accurate, complete, and protected against unauthorized modification. Availability is a security property that ensures information and systems are accessible when needed. Confidentiality, integrity, and availability form the CIA triad. The CIA triad is a foundational model for information security.

An organization protects information by implementing governance, policies, procedures, controls, monitoring mechanisms, and incident response processes. A security policy is a formal document that defines rules and expectations for protecting information. A security standard is a type of control document that defines mandatory requirements. A security procedure is a type of operational document that defines step-by-step activities. A security guideline is a type of advisory document that recommends good practices. A security baseline is a minimum set of controls required for a system, application, or infrastructure component.

The board of directors provides strategic oversight for information security. Senior management approves security policies and allocates resources for security initiatives. The information security manager coordinates the information security program. The asset owner classifies information assets and defines protection requirements. The asset custodian operates and maintains the technical environment that stores or processes information. The system administrator manages servers, networks, operating systems, and technical services. The security analyst monitors security events and investigates suspicious activity. The auditor evaluates compliance with security requirements. The end user accesses systems and must follow security policies.

Risk management is a core process in information security. A risk is the possibility that a threat exploits a vulnerability and causes harm to an asset. A threat is a potential cause of an unwanted incident. A vulnerability is a weakness that can be exploited by a threat. An impact is the consequence produced by a security event or incident. A likelihood is the probability that a risk scenario occurs. A risk scenario describes how a threat may exploit a vulnerability and affect an asset. A control reduces risk by preventing, detecting, correcting, or compensating for security weaknesses.

A preventive control is a type of security control that reduces the probability of an incident. A detective control is a type of security control that identifies suspicious activity or policy violations. A corrective control is a type of security control that restores normal operations after an incident. A compensating control is a type of security control that provides an alternative protection mechanism when a primary control cannot be implemented. Access control is a preventive control. Logging is a detective control. Backup restoration is a corrective control. Manual approval is a compensating control when automated enforcement is not available.

Information classification helps organizations apply appropriate protection levels to different kinds of information. Public information is a type of information that can be disclosed without causing harm. Internal information is a type of information intended for use inside the organization. Confidential information is a type of information whose unauthorized disclosure may harm the organization, customers, employees, or partners. Restricted information is a type of highly sensitive information that requires strict access, storage, and transmission controls. Personal data is a type of sensitive information that identifies or can identify a natural person. Financial data is a type of sensitive information related to payments, accounts, budgets, or financial transactions. Authentication data is a type of restricted information because it can grant access to systems.

Access control regulates who can access which resource and under which conditions. Identification is the process of claiming an identity. Authentication is the process of verifying an identity. Authorization is the process of determining what actions an authenticated identity may perform. Accountability is the ability to trace actions to a specific identity. A user account represents a digital identity. A service account is a type of non-human account used by applications, scripts, integrations, or automated processes. A privileged account is a type of account with elevated permissions. A shared account is a type of account used by multiple individuals and creates accountability risk.

A credential is evidence used to prove an identity. A password is a type of credential. A certificate is a type of cryptographic credential. An access token is a type of temporary credential. An API key is a type of credential used by applications to authenticate requests. A private key is a type of cryptographic secret. A password must be protected against disclosure. A private key must be stored in a secure location. An access token must expire after a defined period. An API key must be rotated periodically. A compromised credential must be revoked immediately.

Multi-factor authentication improves authentication strength by requiring more than one verification factor. A knowledge factor is a type of authentication factor based on something the user knows. A possession factor is a type of authentication factor based on something the user has. An inherence factor is a type of authentication factor based on something the user is. A password is a knowledge factor. A hardware token is a possession factor. A mobile authenticator application is a possession factor. A fingerprint is an inherence factor. Multi-factor authentication reduces the risk of unauthorized access caused by stolen passwords.

The principle of least privilege states that an identity must receive only the permissions required to perform its duties. A permission grants an action over a resource. A role is a collection of permissions. A user group is a collection of identities that share common permissions. A role assignment links a role to an identity. A permission review verifies whether assigned permissions remain necessary. Segregation of duties prevents one person from controlling incompatible activities. Excessive permission is a type of access risk. Dormant account access is a type of access risk. Orphaned account access is a type of access risk.

Identity and access management controls the lifecycle of identities, accounts, roles, permissions, and credentials. User provisioning creates a new user account. User deprovisioning disables or removes access for a user who no longer requires it. Access modification changes the permissions assigned to an identity. Access certification confirms that access remains appropriate. A joiner process creates access for a new employee. A mover process changes access when a person changes role. A leaver process removes access when a person leaves the organization. The identity management system stores identity records. The access management system enforces authentication and authorization decisions.

Network security protects communication channels, network devices, and network services. A firewall is a type of network security control. A network access control system is a type of network security control. An intrusion detection system is a type of detective network control. An intrusion prevention system is a type of preventive network control. A virtual private network protects remote access by creating an encrypted communication tunnel. Network segmentation separates systems into different zones. A demilitarized zone is a type of network segment that exposes controlled services to external networks. A production network is a type of network segment that hosts business systems. A management network is a type of network segment used for administrative access.

Endpoint security protects laptops, desktops, mobile devices, and servers. An endpoint is a device connected to the organizational network. Antivirus software is a type of endpoint protection control. Endpoint detection and response is a type of endpoint security technology. Device encryption protects data stored on an endpoint. Patch management reduces vulnerabilities by applying software updates. Configuration hardening reduces attack surface by disabling unnecessary services and applying secure settings. A laptop is a type of endpoint. A workstation is a type of endpoint. A mobile phone is a type of endpoint. A server is a type of endpoint.

Application security protects software systems throughout their lifecycle. A software vulnerability is a weakness in application code, configuration, or design. Input validation prevents malicious or malformed data from entering an application. Output encoding reduces the risk of injection and cross-site scripting. Secure authentication protects user login processes. Secure session management protects session tokens and user state. Secure error handling prevents sensitive information from being exposed through error messages. A security requirement defines a protection need for an application. A security test verifies whether a security requirement is implemented correctly. A code review examines source code to detect defects, weaknesses, and policy violations.

A web application is a type of application. A mobile application is a type of application. An API is a type of application interface. A database is a type of data storage system. A web server hosts web applications. An application server executes business logic. A database server stores structured data. A load balancer distributes traffic across multiple servers. An API gateway controls access to backend services. A content delivery network improves availability and performance for distributed users. Each technology component may require specific security controls.

Cloud security protects cloud services, cloud infrastructure, cloud workloads, and cloud data. A cloud account is an administrative boundary for cloud resources. A cloud workload is a type of computing resource hosted in a cloud environment. A virtual machine is a type of cloud workload. A container is a type of cloud workload. A serverless function is a type of cloud workload. An object storage bucket is a type of cloud storage resource. A cloud identity is an identity used to access cloud services. A cloud security posture management tool detects misconfigurations in cloud environments. A cloud access security broker monitors and controls cloud service usage.

Cryptography protects information through mathematical techniques. Encryption is a cryptographic mechanism that protects confidentiality. Decryption is the process that converts encrypted data back into readable data. A cryptographic key is a value used by a cryptographic algorithm. Symmetric encryption is a type of encryption that uses the same key for encryption and decryption. Asymmetric encryption is a type of encryption that uses a public key and a private key. A digital signature is a cryptographic mechanism that verifies authenticity and integrity. A hash function generates a fixed-length digest from input data. A message authentication code verifies message integrity and authenticity.

Key management protects cryptographic keys across their lifecycle. Key generation creates a cryptographic key. Key storage protects a cryptographic key from unauthorized access. Key rotation replaces an existing key with a new key. Key revocation invalidates a compromised or obsolete key. Key destruction permanently removes a key from use. A hardware security module is a type of device designed to protect cryptographic keys. A key management service stores and controls access to cryptographic keys. Poor key management can compromise encrypted data.

Logging and monitoring provide visibility into systems, networks, applications, and user activity. A log record is a record of an event generated by a system. An audit log is a type of log that supports accountability and compliance. A security event is an observable occurrence that may be relevant to security. A security alert is a notification generated when a detection rule identifies suspicious activity. A security incident is an event that compromises or threatens confidentiality, integrity, or availability. A false positive is an alert that does not represent a real threat. A false negative is a missed detection of a real threat.

A security information and event management system collects, normalizes, correlates, and analyzes security logs. Log collection gathers records from systems and applications. Log normalization converts different log formats into a common structure. Log correlation identifies relationships between events. A detection rule defines conditions that generate an alert. A use case describes a scenario that monitoring should detect. A dashboard presents security metrics and operational status. A security analyst investigates alerts produced by the monitoring system. A log retention policy defines how long logs must be stored.

Incident response is the process of preparing for, detecting, analyzing, containing, eradicating, and recovering from security incidents. Preparation establishes plans, tools, roles, and communication channels. Detection identifies potential incidents. Analysis determines the scope, cause, and impact of an incident. Containment limits the spread or damage of an incident. Eradication removes the root cause of an incident. Recovery restores systems and services to normal operation. Post-incident review identifies lessons learned and improvement actions. An incident response plan is a document that defines the process for handling incidents.

A malware infection is a type of security incident. A phishing attack is a type of social engineering incident. A ransomware attack is a type of malware incident. A data breach is a type of security incident that involves unauthorized access to or disclosure of data. A denial-of-service attack is a type of availability incident. Unauthorized access is a type of security incident involving access by an unapproved identity. Insider misuse is a type of security incident caused by an internal actor. A lost device incident is a type of physical and information security incident.

Business continuity and disaster recovery protect the organization against major disruptions. Business continuity is the capability to continue critical operations during disruption. Disaster recovery is the process of restoring technology services after a disruptive event. A business impact analysis identifies critical processes, dependencies, and recovery priorities. A recovery time objective defines the maximum acceptable time to restore a service. A recovery point objective defines the maximum acceptable amount of data loss measured in time. A backup is a copy of data used for recovery. A backup policy defines backup frequency, retention, protection, and restoration requirements. A disaster recovery test verifies whether recovery procedures work as expected.

Supplier security manages risks associated with external parties. A supplier is an external entity that provides goods or services. A cloud provider is a type of supplier. A managed service provider is a type of supplier. A software vendor is a type of supplier. A supplier assessment evaluates the security posture of a supplier. A contract defines obligations between the organization and the supplier. A data processing agreement defines responsibilities related to personal data. A service-level agreement defines expected service performance and availability. Third-party access must be approved, monitored, and revoked when no longer required.

Physical security protects facilities, equipment, people, and physical assets. A data center is a type of facility that hosts computing infrastructure. An office is a type of facility where employees perform business activities. A badge reader is a type of physical access control. A security camera is a type of monitoring control. A visitor log records external persons entering a facility. A locked cabinet protects physical documents and removable media. Environmental controls protect equipment from fire, humidity, temperature, and power failures. Physical access to restricted areas must be authorized and monitored.

Human resource security addresses security responsibilities before, during, and after employment. A background check evaluates a candidate before employment. A confidentiality agreement defines obligations related to sensitive information. Security awareness training educates users about policies, threats, and expected behavior. Role-based training provides specialized security knowledge for specific responsibilities. Disciplinary process defines consequences for policy violations. Termination procedure removes access when employment ends. Employees must protect credentials. Employees must report suspected incidents. Employees must follow acceptable use policies.

Security awareness reduces human-related security risks. Phishing awareness teaches users to identify suspicious messages. Password awareness teaches users to create and protect strong passwords. Data handling awareness teaches users to classify, store, transmit, and dispose of information safely. Remote work awareness teaches users to protect devices and networks outside the office. Social engineering awareness teaches users to recognize manipulation attempts. Awareness campaigns reinforce secure behavior. Training completion metrics measure user participation. Simulated phishing exercises measure user response to phishing scenarios.

Compliance ensures that the organization meets legal, regulatory, contractual, and internal requirements. A compliance requirement is an obligation that must be satisfied. A legal requirement is a type of compliance requirement derived from law. A regulatory requirement is a type of compliance requirement imposed by a regulator. A contractual requirement is a type of compliance requirement defined in an agreement. An internal requirement is a type of compliance requirement defined by the organization. Evidence supports the demonstration of compliance. An audit evaluates whether controls satisfy requirements. A nonconformity is a failure to meet a requirement. A corrective action addresses a nonconformity.

Privacy protects personal data and the rights of individuals. A data subject is a person whose personal data is processed. A data controller determines the purposes and means of processing personal data. A data processor processes personal data on behalf of a controller. A privacy notice informs data subjects about processing activities. Consent is a lawful basis for processing in some contexts. Data minimization limits personal data to what is necessary. Purpose limitation restricts processing to defined purposes. Retention limitation restricts how long personal data is stored. Data deletion removes personal data when it is no longer needed.

Data lifecycle management protects information from creation to disposal. Data creation produces new information. Data storage keeps information in a repository. Data processing transforms or uses information. Data transmission moves information between systems or people. Data sharing provides information to another party. Data archival stores information for long-term retention. Data disposal removes information when retention expires. Secure deletion prevents recovery of disposed data. Data classification applies labels to information. Data handling rules define how each classification level must be protected.

Change management controls modifications to systems, applications, infrastructure, and configurations. A change request proposes a modification. A standard change is a type of pre-approved low-risk change. A normal change is a type of change that requires assessment and approval. An emergency change is a type of change implemented rapidly to resolve urgent issues. Change approval verifies that a change is acceptable. Change testing verifies that a change works as intended. Change rollback restores a previous state if a change fails. Unauthorized change is a type of control violation. Poor change management can introduce vulnerabilities.

Vulnerability management identifies, evaluates, prioritizes, and remediates weaknesses. A vulnerability scan detects known vulnerabilities in systems and applications. A vulnerability finding describes a detected weakness. A severity rating estimates the technical seriousness of a vulnerability. A risk rating combines severity, exposure, likelihood, and business impact. Remediation removes or fixes a vulnerability. Mitigation reduces the risk when remediation is not immediately possible. Patch deployment is a type of remediation. Configuration change is a type of remediation. Vulnerability exceptions must be documented, approved, and reviewed.

Threat intelligence provides information about threats, threat actors, tactics, techniques, and indicators. A threat actor is an entity that can intentionally cause harm. A cybercriminal group is a type of threat actor. An insider is a type of threat actor. A nation-state actor is a type of threat actor. A hacktivist is a type of threat actor. An indicator of compromise is evidence that a system may be compromised. A tactic describes a threat actor objective. A technique describes how a threat actor achieves an objective. Threat intelligence supports detection, prevention, and response activities.

Secure architecture integrates security into the design of systems and environments. Defense in depth applies multiple layers of security controls. Zero trust is a security model that assumes no implicit trust based on network location. Network segmentation limits lateral movement. Strong authentication protects access points. Encryption protects data at rest and in transit. Monitoring detects suspicious activity. Backup and recovery support resilience. Secure architecture must align with business requirements, risk appetite, and regulatory obligations.

A security control can protect one or more assets. An asset can be affected by one or more risks. A risk can be reduced by one or more controls. A threat can exploit one or more vulnerabilities. A vulnerability can affect one or more systems. A system can process one or more information assets. A user can access one or more systems. A role can include one or more permissions. A policy can define one or more requirements. A requirement can be satisfied by one or more controls. An incident can affect one or more assets. An incident can trigger one or more response procedures.

For example, a customer database stores personal data and financial data. The customer database is hosted on a database server. The database server runs inside a production network. The production network is protected by a firewall. The firewall enforces network access rules. The customer database is encrypted using a cryptographic key. The cryptographic key is stored in a key management service. The security information and event management system collects audit logs from the database server. A security analyst reviews alerts related to the customer database. The asset owner classifies the customer database as restricted information.

Another example involves remote access. A remote employee uses a laptop to access a corporate application. The laptop is an endpoint. The corporate application is a web application. The remote employee authenticates through multi-factor authentication. The identity provider verifies the employee identity. The authorization service grants access based on role assignments. The virtual private network encrypts the communication channel. The endpoint detection and response tool monitors the laptop. The security policy requires remote employees to report lost devices immediately.

A phishing scenario illustrates how threats, vulnerabilities, controls, and incidents relate to each other. A threat actor sends a phishing email to an employee. The phishing email contains a malicious link. The employee clicks the malicious link and submits a password. The submitted password becomes a compromised credential. The attacker uses the compromised credential to access a cloud account. Multi-factor authentication may prevent unauthorized access. Security awareness training may reduce the likelihood of clicking the malicious link. Email filtering may detect and block the phishing email. Log monitoring may identify suspicious login activity. Incident response may contain the compromised account.

A ransomware scenario illustrates the importance of backups, monitoring, and response. Malware encrypts files on a file server. The file server becomes unavailable to business users. The event affects availability and may affect integrity. Endpoint detection and response may detect the malware activity. Network segmentation may limit the spread of the ransomware. Backup restoration may recover encrypted files. The incident response team may isolate affected systems. The post-incident review may identify missing patches, weak access controls, or insufficient monitoring. Corrective actions may include patch deployment, privilege reduction, and improved detection rules.

A data breach scenario illustrates the importance of access control and data protection. An unauthorized user accesses a restricted document repository. The restricted document repository stores confidential information and personal data. The unauthorized access violates the access control policy. Audit logs record the access event. A detection rule generates a security alert. The security analyst investigates the alert. The incident response team confirms a data breach. The privacy officer assesses whether data subjects must be notified. The legal team evaluates regulatory obligations. The organization implements corrective actions to prevent recurrence.

ORION should be able to identify security concepts, classify hierarchical relationships, and extract meaningful relationships from this text. Information asset, security control, security incident, authentication factor, threat actor, compliance requirement, cloud workload, endpoint, and supplier are important classes. Confidential document, corporate database, customer record, and source code repository are subclasses of information asset. Preventive control, detective control, corrective control, and compensating control are subclasses of security control. Password, certificate, access token, API key, and private key are subclasses of credential. Malware infection, phishing attack, ransomware attack, data breach, denial-of-service attack, unauthorized access, insider misuse, and lost device incident are subclasses of security incident.

The resulting ontology should represent that users access systems, roles include permissions, controls reduce risks, threats exploit vulnerabilities, incidents affect assets, systems process information assets, policies define requirements, requirements are satisfied by controls, suppliers provide services, and auditors evaluate compliance. The ontology should also represent that encryption protects confidentiality, backups support availability, logging supports accountability, and monitoring detects suspicious activity. These relationships make the generated RDF or OWL graph suitable for querying, validation, reasoning, and mining.
