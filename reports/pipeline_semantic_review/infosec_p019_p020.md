# Revisión semántica: infosec_p019_p020

## 1. Lectura independiente

### Resumen

Los párrafos describen dos áreas separadas:

- **p019:** gestión de claves criptográficas: ciclo de vida, generación, almacenamiento, rotación, revocación, destrucción, módulos hardware de seguridad, servicios de gestión de claves y el riesgo modal asociado a una gestión deficiente.
- **p020:** logging y monitorización: visibilidad, registros y logs de auditoría, eventos/alertas/incidentes de seguridad, falsos positivos y falsos negativos.

No hay nombres propios ni individuos particulares. Los sintagmas indefinidos y genéricos describen conceptos o clases, no instancias identificadas.

### Conceptos

- **p019:** key management, cryptographic key(s), lifecycle, key generation, key storage, unauthorized access, key rotation, existing key, new key, key revocation, compromised key, obsolete key, key destruction, use, hardware security module, device, key management service, poor key management y encrypted data.
- **p020:** logging, monitoring, visibility, system, network, application, user activity, log record, record, event, audit log, log, accountability, compliance, security event, observable occurrence, security, security alert, notification, detection rule, suspicious activity, security incident, confidentiality, integrity, availability, false positive, alert, real threat, false negative y missed detection.
- **Entidades/instancias explícitas:** ninguna instancia particular. Todas las menciones son genéricas o definicionales.

### Proposiciones con evidencia

**p019**

1. **EXPLÍCITO:** key management protege claves criptográficas durante su ciclo de vida: “Key management protects cryptographic keys across their lifecycle.”
2. **EXPLÍCITO:** key generation crea una clave criptográfica: “Key generation creates a cryptographic key.”
3. **EXPLÍCITO:** key storage protege una clave criptográfica frente al acceso no autorizado: “protects a cryptographic key from unauthorized access.”
4. **EXPLÍCITO:** key rotation sustituye una clave existente por una nueva: “replaces an existing key with a new key.”
5. **EXPLÍCITO:** key revocation invalida una clave comprometida o una obsoleta: “invalidates a compromised or obsolete key.” La coordinación es disyuntiva; no son dos hechos incondicionales independientes.
6. **EXPLÍCITO:** key destruction elimina permanentemente una clave del uso: “permanently removes a key from use.”
7. **EXPLÍCITO:** un hardware security module es un tipo de device: “is a type of device”.
8. **ENTRAÑADO:** el hardware security module tiene como propósito proteger claves, por pertenecer al tipo de “device designed to protect cryptographic keys”. No debe reducirse a una capacidad incondicional sin conservar el propósito “designed to”.
9. **EXPLÍCITO:** un key management service almacena claves criptográficas: “service stores [...] cryptographic keys.”
10. **EXPLÍCITO:** ese servicio controla el acceso a las claves: “controls access to cryptographic keys.”
11. **EXPLÍCITO:** una gestión de claves deficiente puede comprometer datos cifrados: “Poor key management can compromise encrypted data.” “Can” expresa posibilidad, no hecho categórico.

**p020**

12. **EXPLÍCITO:** logging y monitoring proporcionan visibilidad: “Logging and monitoring provide visibility”.
13. **EXPLÍCITO:** la visibilidad es sobre cuatro ámbitos coordinados: “systems, networks, applications, and user activity.”
14. **EXPLÍCITO:** un log record es un record de un event: “A log record is a record of an event”.
15. **EXPLÍCITO:** dicho event es generado por un system: “event generated by a system.”
16. **EXPLÍCITO:** un audit log es un tipo de log: “An audit log is a type of log”.
17. **EXPLÍCITO:** la clase de log descrita soporta accountability y compliance: “supports accountability and compliance.” Aplicarlo al audit log es semánticamente válido, aunque el antecedente superficial de “that” admite discusión.
18. **EXPLÍCITO:** un security event es un observable occurrence: “A security event is an observable occurrence”.
19. **EXPLÍCITO:** ese occurrence puede ser relevante para security: “may be relevant to security.” “May” debe conservarse.
20. **EXPLÍCITO:** un security alert es una notification: “A security alert is a notification”.
21. **EXPLÍCITO:** la notification se genera cuando se cumple una condición: “generated when a detection rule identifies suspicious activity.”
22. **EXPLÍCITO, bajo condición:** una detection rule identifica suspicious activity; esta proposición forma parte de la condición de generación de la alerta, no es una afirmación contextual independiente.
23. **EXPLÍCITO:** un security incident es un event: “A security incident is an event”.
24. **EXPLÍCITO con alcance disyuntivo:** el event “compromises or threatens confidentiality, integrity, or availability.” El texto permite las combinaciones entre los dos predicados y los tres objetos, pero no entraña seis afirmaciones positivas simultáneas.
25. **EXPLÍCITO:** un false positive es un alert: “A false positive is an alert”.
26. **EXPLÍCITO y negativo:** el alert no representa una amenaza real: “does not represent a real threat.”
27. **EXPLÍCITO:** un false negative es una missed detection: “A false negative is a missed detection”.
28. **EXPLÍCITO:** la detección omitida es de una amenaza real: “of a real threat.”

Normalizaciones admisibles: **“LogRecord records Event”** y **“FalseNegative misses RealThreat”** son **ENTRAÑADAS**, no formulaciones literales. **“FalsePositive represents RealThreat”** sin polaridad negativa está **CONTRADICHO** por p020. **“KeyManagement can compromise EncryptedData”** sin el modificador *poor* es **NO SOPORTADO** por p019.

### Taxonomías explícitas

- **p019:** HardwareSecurityModule ⊑ Device.
- **p020:** LogRecord ⊑ Record; AuditLog ⊑ Log; SecurityEvent ⊑ ObservableOccurrence; SecurityAlert ⊑ Notification; SecurityIncident ⊑ Event; FalsePositive ⊑ Alert; FalseNegative ⊑ MissedDetection.

No se justifican aserciones de tipo sobre individuos porque el texto no identifica instancias particulares.

### Modalidad

- **Posibilidad:** “can compromise” (p019) y “may be relevant” (p020).
- **Propósito:** “designed to protect” (p019).
- **Manera/aspecto:** “permanently removes” (p019).
- **Negación:** “does not represent” (p020).
- **Condición temporal/lógica:** “generated when” (p020).
- **Disyunción:** “compromised or obsolete” (p019) y “compromises or threatens [...] or availability” (p020).
- **Conjunción:** “stores and controls”, “Logging and monitoring”, la lista de cuatro ámbitos y “accountability and compliance”.
- El resto son afirmaciones genéricas en presente; no describen episodios individuales.

### Ambigüedades

- **ENTRAÑADO:** en p019, “their” refiere a “cryptographic keys”; es el único antecedente plural compatible. Convertirlo en `CryptographicKeyLifecycle` es una normalización admisible si se conserva su función contextual.
- **PLAUSIBLE:** en p020, el “that” de “a type of log that supports...” tiene como antecedente sintáctico inmediato `log`; atribuir el soporte a `AuditLog` es semánticamente razonable por la definición completa, pero no justifica un span que mezcle sujeto y predicado.
- **ENTRAÑADO:** los otros relativos caracterizan, respectivamente, el observable occurrence/security event, el event/security incident y el alert/false positive.
- **NO SOPORTADO:** materializar por separado las seis combinaciones del incidente como seis hechos incondicionales. Solo es fiel una representación agrupada de la disyunción.
- **NO SOPORTADO:** tratar los sintagmas indefinidos como individuos concretos.
- **CONTRADICHO:** afirmar positivamente que un false positive representa una real threat.

## 4. Diagnóstico

- **Primera degradación:** paso 05. La oración del key management service queda mal analizada al tratar `stores` como sustantivo raíz. Las etapas 01–04 preservan íntegramente texto, offsets, oraciones y tokens.
- **Principal pérdida:** paso 09. La extracción relacional elimina modificadores (`poor`), modalidad (`can`, `may`), negación, argumentos preposicionales, propósitos, condiciones y alcance coordinado. Su error más grave es invertir la definición del false positive.
- **Principal contenido no soportado:** `alert represent real threat` en 09, contradicho por p020. No llega al output final porque 10/12/16 restauran la polaridad negativa.
- **Errores que llegan a RDF/OWL:** no llega ningún hecho positivo claramente contradicho por los párrafos. Sí llega duplicación estructural de clases, taxonomías y vistas de propiedades. La condición `generated when` se conserva mediante `context`, `relation_role` y `state`, pero no como una construcción RDF estándar; su interpretación depende del consumidor.
- **Aciertos:** 10 reconstruye con alta fidelidad las 34 unidades semánticas, incluidas modalidad, negación, propósito, targets, topics y grupos alternativos; 12 conserva esos metadatos; 13 obtiene exactamente las ocho taxonomías explícitas; 14 evita inventar instancias; 16 no materializa como hechos simples los claims modales, negativos o disyuntivos y los separa en `scoped_relations` y `logical_alternatives`.
- **Incertidumbres:** el alcance sintáctico del relativo en la definición de audit log y la expansión combinatoria del security incident requieren representación agrupada. ORION adopta interpretaciones plausibles y, en el caso del incidente, conserva un único grupo disyuntivo; no debe leerse cada alternativa como hecho independiente.
